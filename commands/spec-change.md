---
description: Propose a spec change properly — never silently diverge
---

Something is ambiguous or wrong in the spec. Run the change properly: (1) state the problem — what the spec says, what reality demands, where it bit ($ARGUMENTS if provided); (2) propose the minimal edit — exact section, old wording → new wording, and any ripple (other sections, plan items, Jira stories affected); (3) wait for approval; (4) on approval: edit the repo spec, republish the Confluence spec page, add the Decision Log row, and comment on any affected Jira issues so building agents see the change. Never batch unrelated changes into one proposal.
